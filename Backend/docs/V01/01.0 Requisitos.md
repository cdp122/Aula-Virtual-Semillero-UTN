# Síntesis de Requisitos Funcionales (RQ) para el Backend

El sistema en su primera versión se tiene planteado realizar avances en backend para un POC, una demo funcional pero solo con lo estrictamente necesario para funcionar. 

## Infraestructura tecnológica

Se plantea desarrollar con node usando graphql con mongodb con doble cluster local para soportar transacciones. 

## GraphQL

Además de tener las tipicas mutaciones y queries de cada entidad se despliegan las siguientes mutaciones para apoyar al equipo de frontend:

### Módulo: Autenticación y Usuarios (Transversal)

* **`Mutation: login(username, contrasena)`**: Retorna un payload solo con los datos del usuario, esto se mantiene de manera temporal en la fase de POC. Si es Padre, debe incluir el array de `hijos`; si es Docente, las aulas asociadas. Por el momento Frontend almacenará localmente este payload para poder autenticarse. Cuando entremos en fase development oficial se ocupará el confiable JWT para las autenticaciones. 

### Módulo: Docente (Microaula Virtual)

* **`Mutation: crearUnidadDidactica(input)`**: Registra la planificación dinámica (ámbito, objetivos, destrezas).
* **`Mutation: agregarActividadAUnidad(unidadId, input)`**: Inserta una actividad con sus criterios y descriptores en el array de la unidad.
* **`Mutation: registrarEvaluacion(estudianteId, actividadId, criteriosInput, fichaInput)`**: Inserta un nuevo elemento en el `historial_versiones` del estudiante. **Importante:** No borra ni sobreescribe la versión anterior para cumplir con el **RNF-06**.
* **`Query: obtenerReporteGrupal(cursoId, actividadId)`**: Retorna el conteo consolidado de alumnos por nivel (*Iniciado/En Proceso/Logrado*) usando agregaciones de Mongo (**RF-D05**).
* **`Mutation: registrarAutoevaluacionDocente(actividadId, respuestasInput)`**: Guarda el formulario reflexivo del maestro de forma privada (**RF-D07**).

### Módulo: Familia (Padre de Familia)

* **`Query: obtenerProgresoHijo(estudianteId)`**: Retorna la última versión registrada de las notas y las observaciones de apoyo del docente, filtrando tecnicismos pedagógicos de acuerdo al **RF-F02** y **RNF-08**.
* **`Query: obtenerActividadesCasa(estudianteId)`**: Lista las tareas de extensión asignadas cronológicamente para que el padre las visualice fácilmente.
* **`Mutation: marcarActividadCompletada(estudianteId, actividadId, comentario)`**: Permite al padre notificar que realizó la guía de la semana con el niño (**RF-F04**).

### Nota:

Para las entidades que se cachearán en el servidor debemos de agregar que por cada actualización a dichas entidades se debe volver a consultar a la BDD para que se ingresen los nuevos datos a caché.
